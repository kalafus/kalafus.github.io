Getting started

Move carefully. Keep control.

A short path from ordinary cloud Contacts to an encrypted vault, with the system-facing view you choose.

Import and encrypted vault sync start on. Cleanup of synced-account originals defaults off and requires an account choice. Editable iPhone/iPad sharing can separately consolidate validated local duplicates. Keep an independent backup and check validation before enabling account removal.

1. Keep an independent backup

Before changing Apple Contacts, keep an independent backup of each source account. For iCloud, export your contacts as a vCard. On a Mac, a Contacts Archive can preserve more address-book structure. Proto Contacts can import both formats. After importing, you can also make a portable backup of the full vault.

2. Choose accounts and your Me Card

Proto Contacts imports supported CardDAV and Exchange cloud accounts connected through Apple Contacts, including iCloud, as well as local contacts. Open Set Up Contacts on the main screen or in Settings. The guide saves progress; use Continue Setup in Settings or the ellipsis menu to return later. Closing or skipping unfinished setup keeps original removal paused.

  1. Grant Contacts access when requested. Full access is needed for a complete import and source cleanup; limited access sees only selected cards.
  2. Open Accounts. Under Import Contacts, choose the supported local, Exchange, and CardDAV accounts you want to import. Newly discovered accounts default to importing while keeping their originals. Turning import off clears that account’s removal choice; turning it back on leaves removal off.
  3. On iPhone or iPad, choose Choose Me Card… and select the card marked My Card in Apple Contacts. If none exists, choose I Have No Me Card and confirm. On Mac, the app identifies the system Me Card automatically. You can also mark a vault contact through This Is My Card in its context menu.

Your Me Card is imported into the encrypted vault when its account is selected, including when Include Me Card is off. That switch controls this device’s system sharing and original removal. Off protects the originals and withholds the app’s shared copy. On allows the same sharing and validated removal rules as other contacts. Review the choice in Settings → Apple Contacts Integration → Me Card.

Remove Validated Originals applies to eligible synced accounts and starts off. Local accounts do not use that account-removal switch; editable iPhone/iPad sharing has separate duplicate-repair and deletion rules below. Saved account choices apply to this device; existing removal selections may differ from the new-vault defaults.

3. Import, validate, and review

Setup follows Import → Sync Review Information → Validation → Review → System Contacts Sharing. Choose Start beside Import Contacts. The app checks for current review information from your other devices, then shows validation and differences. Slow or offline review downloads can be deferred; unresolved reviews remain available afterward.

Continue advances from Review without resolving every difference. Done can finish setup with originals kept while system sharing continues preparing. If you selected removal, the final removal step requires sharing readiness, a successful encrypted vault sync, and fresh complete validation. Setup does not use force removal.

Use Settings → Apple Contacts Integration → Import & Review for Import Now, Review Differences, and Validation Details. Validation Details counts source records that have not passed validation and explains why. Refresh Import & Validation in setup explicitly retries those checks. Unreadable fields, missing assets, incomplete visibility, and unresolved differences can keep originals in place.

Import File… in the ellipsis menu accepts vCards, Apple Contacts Archives, and Proto Contacts backups. Review the preview before adding and merging records. Existing contacts are kept; competing values go through normal review. Apple’s public Contacts API does not expose Contact Poster designs.

Local duplicate repair on iPhone and iPad

With setup complete and editable local sharing enabled, normal import and sharing retry cleanup of multiple native cards already linked to one vault contact. Import Now also discovers new independent cards. The app keeps an existing native card that preserves the family’s information, or completes it from compatible data already in those native cards before verifying it and removing extras. Vault-only fields are not added to complete a keeper.

Unreadable fields, unpreserved assets or native list memberships, unresolved differences, Me Card protection, import opt-outs, and export or recovery pauses can hold cleanup. A shared name alone does not make contacts duplicates. System Contacts Sharing → Additional Apple Contacts records shows linked extras, the contacts involved, and current hold reasons. Fix the reported cause; ordinary sharing retries safe repairs.

4. Choose what other apps see

Open Settings → System Contacts Sharing. In Contacts shared with system, the Share All Contacts with iOS/macOS switch chooses the baseline: on shares all except the Mask List; off shares only the Share List. Both lists are retained. Choose Apply to save this device’s choices, then use Choose published fields for All, Minimalist, None, or individual fields. All supported fields are selected by default. List membership stays in the vault.

Contact Posters: Apple’s public Contacts API exposes contact photos, but not Poster designs. Photos can be shared when selected; full-screen Posters cannot be recreated in the shared cards. Keep original Apple Contacts cards if you need their Posters. Vault validation does not verify Poster preservation.

Where shared contacts appear

  • iPhone/iPad with cloud Contacts enabled: While any cloud Contacts account, such as iCloud, Google, or Exchange, is enabled in Apple’s system settings, Proto Contacts uses Apple’s read-only Contact Provider with system approval.
  • iPhone/iPad with all cloud Contacts disabled: Proto Contacts shares into the editable on-device address book, shown as iPhone or iPad. Full Contacts access, enabled System Contacts Sharing, and an available local destination are required.
  • Mac: Proto Contacts uses On My Mac when available. See Mac setup if that account is missing or disappears.

These are Apple’s Contacts account sync controls. Turning an account’s import off inside Proto Contacts does not change the sharing route. Encrypted Vault Sync is separate from these native Contacts sync settings.

Contacts ready to share reports prepared contacts; provider enrollment alone does not establish that they are visible in Apple Contacts. Manual enable/disable is under Advanced.

Sharing saved contacts can continue during a vault-sync outage. Masking or disabling sharing withdraws the app’s copies; independent native account copies and data another app has saved remain separate. Foreground approval reminders stop after three refusals or an explicit disable. Background import and sync do not present permission prompts.

Missing contacts and explicit deletion

In editable iPhone/iPad sharing, deleting a contact from the vault can also remove its linked, unchanged local original and the app’s shared copy. Me Card protection still applies; changed native data needs review. Deletions detected in Apple Contacts keep vault contacts pending a decision.

Open Review Missing Contacts, or Differences → Missing Contacts → Review Deletions…, to choose deletion, restoration, or which contacts to keep. Restore All keeps the vault contacts and restores local system copies according to your sharing choices; Undo is available until you leave that review. Keeping cloud-account contacts does not recreate their server originals.

For stale or incomplete shared copies, use Advanced → Rebuild Shared Contacts. The read-only provider reloads its derived view. Local sharing repairs missing copies in place, with the duplicate-repair rules above still applying, and keeps vault contacts when resolving its mirror-deletion reviews. Use the missing-contacts review for deliberate restore/delete choices and Undo.

Private sharing on Mac

Proto Contacts can use On My Mac alongside cloud Contacts accounts when Apple makes it available. You may need to disable Contacts sync for every cloud account, including iCloud, to make it appear or keep it available. We have observed this availability issue, but have not confirmed an Apple requirement or its cause; an Apple Contacts bug is a possibility.

  1. Back up, import, and validate every account you want to preserve, including your Me Card. Resolve differences and verify encrypted vault sync.
  2. If On My Mac is unavailable, or you want to stop native cloud Contacts sync, choose Contacts → Accounts in Apple Contacts, select each cloud account, and turn off Contacts. Apple documents this account control. Keep Proto Contacts’ Encrypted Vault Sync and iCloud Passwords & Keychain on.
  3. Check for On My Mac in Apple Contacts’ Lists sidebar, then choose Check Again in Proto Contacts’ system-sharing settings to refresh the available destination.

If offered, Finish System Contacts Sharing Setup… in the ellipsis menu and System Contacts Sharing → Mac privacy setup provide the same steps. You can also change account sync directly in Apple Contacts. Disconnecting an account suspends it and leaves server copies in place. Original removal is a separate operation and pauses while a requested local mirror is unavailable.

Display preferences are in iPhone/iPad Settings → Apps → Proto Contacts, or inside the app’s Settings on Mac (⌘,). Date Reminders in app Settings controls local birthday and other date notifications. Names are hidden in notifications by default; enabling them can expose those details in notification previews.

5. Sync your encrypted vault between devices

Sync encrypted vault between devices starts on for new vaults. Use the same Apple Account and enable Passwords & Keychain. The app encrypts vault contents before sending them to private CloudKit storage; the key travels separately through end-to-end-encrypted iCloud Keychain. This gives stored vault contents zero-access encryption. Ordinary setup requires no manual key copying or Advanced Data Protection setting.

Sync Now requests incoming changes as well as uploads. Check Settings → Encrypted Vault Sync for status, pending uploads, any scheduled retry, and error details. Local work stays available during network waits. A new empty device can wait for the existing vault before automatically importing Apple Contacts. Devices that started independently keep their local records; matching records consolidate, uncertain matches need review, and Merge history → Undo merge can separate a merge.

You can turn sync off in Settings; an existing saved opt-out stays off. Account import and system sharing remain separate controls.

6. Back up and plan recovery

Portable offline backups

Choose Settings → Encrypted Vault Sync → Advanced Recovery → Export Backup…. The backup includes contacts, lists, photos, history, and pending reviews. Export does not require resolving those reviews first.

Password protection and the post-quantum encryption layer have independent secrets. Both default on. Save the archive password and generated backup recovery key separately from the file; both are needed when both layers are enabled. These are different from your active vault recovery key, and neither the app nor iCloud can recover them. Disabling both layers requires confirmation and creates a readable file.

Wait for the app to verify the saved file. Use Import Contacts or Backup… to authenticate, preview, and add or merge it into the current vault. Import preserves existing contacts and can leave differences for review. Test recovery while you still have your working vault.

Estate access

Consider an Apple Legacy Contact for Apple Account data. In Apple Settings use [your name] → Sign-In & Security → Legacy Contact. Apple reviews an access request using the person’s Legacy Contact key and required supporting documentation. That access excludes iCloud Keychain and does not supply Proto Contacts’ vault key.

An offline backup, its chosen encryption secrets, and tested extraction instructions can provide a route independent of iCloud. A manually copied vault recovery key alone is not a backup of your contacts. Proto Contacts has no automatic estate handoff; plan access to the archive and its secrets separately from Apple Account inheritance.

7. Export to Apple Contacts, including iCloud

Open Settings → Apple Contacts Integration → Accounts → Export Contacts… and select a configured supported account. The destination can differ from your import accounts. Export makes readable native copies under that account’s security rules and keeps the encrypted vault.

  1. Pause original removal on your other devices and wait for running imports to finish. Confirm this in the export screen; offline devices and already-running imports may not have received a shared pause.
  2. Choose Turn Off Removal & Prepare…. This durably turns off removal and automatic import before checking access. When vault sync is enabled, a successful current sync is also required and shares the pause with linked devices. Cancellation, relaunch, and local settings reset do not cancel that pause.
  3. Review the destination and plan. Complete independent copies are reused. Similar contacts with different details require confirmation to create separate copies; existing native records are never overwritten. For Exchange destinations, exporting lists is unavailable and requires an explicit contacts-without-lists choice.
  4. Choose Export to [account]…, confirm, and wait for read-back verification. Supported fields, list memberships where available, and displayed photo crops are included regardless of system-sharing filters. Original photos stay in the vault. Contact Posters cannot be recreated in these exports because Apple’s public Contacts API does not expose their designs.
  5. Verify delivery to the destination’s other devices. Finish & Turn Off System Sharing checks the recorded export again before withdrawing this device’s provider or mirror. The vault, history, keys, and encrypted sync remain.

After an interruption, prepare a fresh plan on the same device so saved progress can be reconciled. Local verification does not establish server or other-device delivery. Keep removal paused until you deliberately resume it through Accounts, and check every wanted copy before uninstalling. This preview still needs signed-device testing with real account providers.

8. Reset preferences or the database

Reset App Settings to Defaults… requires confirmation and restores account, sync, sharing, display, and Me Card preferences. Original removal defaults off. Contacts, lists, history, keys, permissions, and setup progress are kept; a shared export pause remains in effect.

Advanced Recovery → Reset Database on All Devices… is a separate destructive action with two confirmations. It erases vault data and history on this device and on updated linked devices when they next sync. Keys and app settings remain. Existing writable Apple Contacts cards—including previously shared copies—keep their native identifiers; the app retires their old ownership mappings. The read-only provider’s derived view is cleared. Back up first: removed originals are not recreated by reset, and an offline device cannot be erased until it reconnects.

Proto Contacts is a developer preview. Keep an independent backup while evaluating migration. See the FAQ for privacy, recovery, and support.
